# 简历项目写法指南：Bili Music Qt 客户端

这份文档帮你把项目写进简历，并准备面试时怎么讲。核心原则是：写真实做过的工程能力，不夸大，不把个人客户端包装成商业级平台。

## 1. 项目定位

推荐定位：

> Bili Music 是一个基于 Qt 6、C++17 和 QML 实现的桌面音乐客户端，支持 B 站登录态管理、收藏夹内容浏览、媒体播放地址解析、播放队列管理、播放器控制和响应式 QML 界面。

适合投递方向：

- C++ 客户端开发实习
- Qt/QML 开发实习
- 桌面应用开发
- 音视频应用开发
- 通用 C++ 软件开发

不建议把它作为主项目投递的方向：

- 后端高并发服务
- 算法工程
- 嵌入式底层驱动

这些方向也可以保留这个项目，但最好再搭配一个更贴近岗位的项目。

## 2. 简历里可以这样写

项目名称：

> Bili Music：基于 Qt/C++ 的 B 站音乐桌面客户端

技术栈：

> C++17、Qt 6、QML、Qt Quick、Qt Network、Qt Multimedia、CMake、JSON、Git

项目描述：

> 使用 Qt 6 + C++17 开发桌面音乐客户端，支持 B 站登录态管理、收藏夹内容浏览、媒体播放地址解析、播放队列管理、播放控制和响应式 QML 界面。

职责与亮点：

- 设计 C++ 服务层与 QML 展示层分离的客户端架构，通过 `ApplicationContext` 统一暴露认证、收藏夹、媒体解析、播放控制、播放队列和本地设置等服务。
- 封装基于 `QNetworkAccessManager` 的异步网络访问层，统一处理请求头、Cookie 会话、超时、JSON 解析和错误返回。
- 实现收藏夹概览与详情页状态切换，点击收藏夹后只展示当前收藏夹内的视频列表，并处理异步加载中的旧响应覆盖问题。
- 基于 Qt Multimedia 封装播放控制逻辑，实现播放、暂停、进度同步、音量控制、上一首、下一首、播放模式和播放队列持久化。
- 使用 QML 组件化重构界面，建立全局设计令牌和通用组件，支持窗口自由缩放、窄宽度侧栏收起和播放器控件压缩。
- 补充 Qt Test 与 QML 测试，覆盖收藏夹加载会话、媒体解析、本地设置和主要界面组件行为。

如果简历空间很紧，可以压缩成三条：

- 使用 Qt 6 + C++17 实现桌面音乐客户端，覆盖登录态管理、收藏夹浏览、媒体解析、播放控制和播放队列管理。
- 采用 C++ 服务层 + QML 展示层分离架构，通过 `Q_PROPERTY`、`Q_INVOKABLE` 和 Qt 信号槽完成异步业务状态同步。
- 组件化重构 QML 界面，建立全局设计系统，支持响应式布局、窄窗口导航收起和播放器控件压缩。

## 3. 最值得突出的技术点

完整客户端工程：

这个项目不是单个 demo，而是包含 UI、网络、会话、第三方接口、播放器、持久化、测试和构建系统的完整桌面客户端。简历里要突出“完整链路”，不要只写“实现音乐播放”。

C++ 与 QML 分层：

可以强调业务逻辑没有堆在 QML 里。网络、认证、播放、设置这些状态复杂的逻辑放在 C++ 服务层；QML 负责展示、布局和交互。这样后续维护和排查问题更清楚。

异步请求和状态保护：

收藏夹、扫码登录、媒体解析都涉及异步结果。项目里通过 generation、session、owner tag 等方式避免旧请求覆盖新页面状态，这是很值得讲的工程细节。

播放链路：

可以讲 `MediaResolver` 和 `PlayerController` 的职责划分：前者负责拿到真实媒体地址，后者负责播放控制、状态同步和错误处理。不要说“自研播放器内核”，更准确的说法是“基于 Qt Multimedia 封装播放控制”。

响应式 QML 界面：

新版界面不是简单美化，而是建立了设计系统和布局框架：统一主题令牌、通用按钮/图标/列表组件、三档窗口宽度适配、播放队列抽屉和降低动态效果设置。

## 4. 面试时怎么讲

30 秒版本：

> 这是一个用 Qt 6 和 C++17 写的 B 站音乐桌面客户端。界面层用 QML，业务逻辑放在 C++。我主要实现了登录态管理、收藏夹数据加载、媒体播放地址解析、播放器控制、播放队列管理，以及一套响应式 QML 界面。这个项目让我比较系统地练习了 Qt 的信号槽、C++/QML 交互、异步网络请求、Cookie 持久化、Qt Multimedia 和客户端架构拆分。

如果面试官问“为什么用 Qt/QML，不用 Electron”：

> 我想重点练习 C++ 客户端开发，所以选择 Qt。Qt 的对象模型、信号槽、Network、Multimedia 和 QML 都比较适合做桌面客户端。QML 写界面效率高，C++ 又能承载网络、播放和本地状态这些更偏工程逻辑的部分。

如果面试官问“C++ 和 QML 怎么通信”：

> C++ 侧把服务对象通过 `ApplicationContext` 注入到 QML 上下文。QML 读取状态用 `Q_PROPERTY`，调用业务方法用 `Q_INVOKABLE`，异步结果通过 Qt 信号返回。比如收藏夹加载完成后，C++ 发出包含 JSON 的信号，QML 解析后刷新列表。

如果面试官问“点击一首歌后发生了什么”：

> QML 先把当前条目交给播放队列服务，然后调用媒体解析服务。`MediaResolver` 根据条目的类型、BVID、CID 等信息请求真实播放地址，解析完成后交给 `PlayerController`。播放器控制器再设置媒体源、开始播放，并通过属性和信号把播放状态、进度、错误信息同步回 QML。

如果面试官问“你解决过什么具体问题”：

> 一个典型问题是收藏夹异步加载。用户快速切换收藏夹时，旧请求可能比新请求更晚返回，如果不处理就会覆盖当前页面。我用加载会话和请求归属标记判断响应是否仍属于当前视图，只接收最新会话的数据。这个问题后来也加了单元测试。

## 5. 不要这样写

不建议使用这些表述：

- 自研播放器内核
- 破解 B 站接口
- 商业级音乐平台
- 高并发音乐服务
- 分布式音视频系统
- 支持海量用户

更稳妥的表述：

- 基于 Qt Multimedia 封装播放控制
- 对接第三方接口并处理会话、请求头和异步回调
- 实现可运行的桌面客户端原型
- 完成从 UI 到网络再到播放的核心链路
- 建立组件化 QML 界面和响应式布局框架

## 6. 面试前建议准备

准备四样东西就够了：

- 一张架构图：QML 层、`ApplicationContext`、业务服务层、网络层、播放层。
- 一个 1 分钟 demo：打开应用、进入收藏夹、点开一个收藏夹、播放条目、打开播放队列、缩窄窗口看响应式布局。
- 三个重点源码文件：`ApplicationContext`、`FavoriteService`、`PlayerController`。
- 一个改进计划：Cookie 本地加密、接口失败重试、缓存、更多测试、跨平台打包。

如果只能在简历里放一段，建议这样写：

> **Bili Music：基于 Qt/C++ 的 B 站音乐桌面客户端**  
> 技术栈：C++17、Qt 6、QML、Qt Network、Qt Multimedia、CMake  
> 使用 Qt 6 + C++17 实现桌面音乐客户端，支持登录态管理、收藏夹内容浏览、媒体播放地址解析、播放控制和播放队列管理。项目采用 C++ 服务层与 QML 展示层分离的架构，通过 `ApplicationContext`、`Q_PROPERTY`、`Q_INVOKABLE` 和信号槽完成业务服务暴露与异步状态同步；封装网络访问、Cookie 持久化、媒体解析和播放器控制模块，并组件化重构 QML 界面，支持响应式布局和统一设计系统。
