# Qt/C++ 教学型源码注释设计

## 目标

把 `cursor_music` 项目的手写 Qt/C++ 与 QML 源码逐步改造成适合初学者阅读的“教学型源码”。注释应帮助读者在尽量少跳转文件的情况下理解类关系、对象关系、信号槽、QML/C++ 数据流、状态变化、生命周期、异步控制流和事件循环。

本工作只修改注释和配套阅读文档，不改变接口、业务逻辑、对象所有权、信号槽连接、线程模型或运行行为。

## 覆盖范围

需要处理：

- `src/` 下项目维护的 `.h` 与 `.cpp` 文件；
- `qml/` 下项目维护的 `.qml` 与 `.js` 文件；
- `tests/` 下有助于解释生产代码行为的测试源码；
- 必要的项目阅读文档。

不处理：

- `build-*`、CMake 自动生成文件、MOC/RCC/QML cache 产物；
- `.git`、IDE 配置与临时输出；
- `哔哩哔哩API/` 下的第三方资料；
- 图片、字体、音频等资源文件。

## 处理顺序

采用“按运行链路逐模块深入”的顺序：

1. 启动与装配：`main.cpp`、`ApplicationContext`；
2. 基础设施：`AppSettings`、`PersistentCookieJar`、`HttpClient`；
3. API 与认证：`BilibiliApiClient`、`AuthService`；
4. 业务数据：`FavoriteService`、`FavoriteLoadSession`、`MusicService`；
5. 播放链路：`MediaResolver`、`PlayerController`、`PlaylistService`；
6. QML 入口与外壳：`Main.qml`、`AppShell.qml`；
7. QML 页面与组件；
8. 对应测试源码与全局阅读文档复核。

第一批处理 `ApplicationContext.h/.cpp`。分析时同时只读追踪 `main.cpp`、`Main.qml` 以及各服务构造函数，但不把这些文件混入同一批修改。

## 单批工作单元

普通 C++ 类以一对 `.h + .cpp` 为一个工作单元。只有单文件的入口、独立头文件、QML 文件或 JavaScript 文件各自作为一个工作单元。

每个 C++ 工作单元按以下顺序处理：

1. 先完整阅读头文件，再阅读实现文件；
2. 搜索类的创建位置、持有者、父对象和销毁路径；
3. 搜索成员声明、构造初始化、setter 与关键使用位置；
4. 搜索全部 `connect()`、信号发送处与可确认的接收者；
5. 搜索 `Q_PROPERTY`、`Q_INVOKABLE`、slots 和 QML 调用位置；
6. 识别网络、定时器、事件循环、多线程及延迟销毁流程；
7. 添加教学型注释；
8. 编译或运行与该模块风险相称的测试；
9. 输出该工作单元的阅读地图。

## 注释结构

### 类级说明

每个核心类在声明前说明：

- 继承关系及 QObject/元对象系统是否参与；
- 职责边界；
- 主要协作者；
- 对象所有权；
- QML 暴露方式；
- 关键数据流或控制流。

### 成员来源

成员变量第一次关键出现时标明其类型、声明位置、用途和所有权。函数参数、局部变量、父类成员、框架对象与 QML 注入对象只在首次或容易误判的位置标明来源，避免重复注释。

### Qt 隐式机制

重点解释：

- `Q_OBJECT`、`Q_PROPERTY`、signals、slots、`Q_INVOKABLE`；
- `connect()` 的发送者、信号、接收者、槽/Lambda、触发条件和连接语义；
- `emit` 后可确认的 C++ 接收者及 QML 属性绑定刷新；
- QObject 父子生命周期、非拥有指针和 `deleteLater()`；
- 事件循环、定时器、网络回调、queued connection 与线程亲和性；
- Model/View 回调及模型变更通知协议；
- QML 到 C++ 的调用入口与 C++ 到 QML 的通知链路。

无法从项目中确认的关系必须明确标为未知或推断，不根据变量名编造职责。

### 函数结构

长函数按业务阶段分段。超过约 40 至 50 行且存在分支、回调或多个状态阶段的函数，在开头增加紧凑的流程地图。简单 getter、机械容器操作和显而易见语句不做逐行翻译。

## 文件编码与现有注释

当前源码包含中文注释。修改时保持 UTF-8 编码，并修正与当前实现不一致的旧注释，例如已从 context property 改为 `setInitialProperties()` 的 QML 注入路径。已有准确且有教学价值的注释应保留或整合，避免在其旁边堆叠重复说明。

## 验证策略

每批至少执行：

- 检查差异，确认除注释和文档外无行为变化；
- 使用现有 CMake 构建验证 C++/MOC/QML 语法；
- 运行与当前模块直接相关的单元测试或 Qt Quick 测试；
- 若缺少专门测试，至少运行现有完整测试集中的可用部分。

注释变更不新增只为覆盖注释而存在的测试。

## 单批交付内容

每个工作单元完成后，向用户提供：

1. 文件职责；
2. 类关系；
3. 核心成员变量；
4. Signal/Slot 关系；
5. QML/C++ 数据流；
6. 对象生命周期；
7. 异步流程；
8. 最值得优先阅读的函数及顺序；
9. 阅读该文件所需的 Qt 知识；
10. 修改文件与验证结果。

## 完成标准

项目范围内每个手写源码文件均完成审阅，并在需要的位置具备准确、非重复、面向关系与控制流的教学注释。所有可用构建和测试保持通过，最终阅读文档能串联启动、认证、收藏夹、网络、播放和 QML 界面六条主要链路。
