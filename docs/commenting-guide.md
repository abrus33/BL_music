# 项目注释规范

这份规范面向后来接手项目的 C++/Qt 初学者。目标不是把每一行代码翻译成中文，而是让新人能快速回答三个问题：

1. 这个文件负责什么？
2. 这段代码为什么要这样写？
3. 这段代码和其他模块怎么协作？

## 注释分层

### 文件头注释

每个核心源文件开头说明：

- 文件在项目中的角色。
- 主要依赖哪些模块。
- 新人第一次阅读时应该重点看什么。

示例：

```cpp
// PlayerController 只关心“怎么播放”，不关心“播放地址怎么来”。
// 播放地址由 MediaResolver 解析，播放器拿到 URL 后负责下载、缓存和控制进度。
```

### 类注释

类注释回答：

- 这个类的职责边界。
- 是否暴露给 QML。
- 是否拥有其他 QObject 的生命周期。
- 是否有异步回调或信号。

不要在类注释里列所有成员函数，成员函数名本身已经能说明很多事情。

### 函数注释

只给关键函数写函数级注释，重点解释：

- 输入参数代表什么。
- 返回值或信号什么时候触发。
- 异步函数的结果在哪里回来。
- 失败时会怎么处理。

简单 getter/setter 不需要注释。

### 代码块注释

代码块注释解释“为什么”，少解释“是什么”。

推荐：

```cpp
// QMediaPlayer 不能给 CDN 请求补 Referer，所以这里先自己下载到 QBuffer。
```

不推荐：

```cpp
// 设置 request 的 User-Agent。
request.setRawHeader("User-Agent", ...);
```

## Qt/QML 必须解释的概念

新人第一次读 Qt 项目时最容易卡在框架机制上，所以遇到下面内容时要主动解释：

- `Q_OBJECT`：启用 Qt 元对象系统，信号槽和 Q_PROPERTY 都依赖它。
- `Q_PROPERTY`：把 C++ 属性暴露给 QML 绑定。
- `Q_INVOKABLE`：允许 QML 像调用 JS 函数一样调用 C++ 方法。
- `signals`：C++ 异步结果通知 QML 或其他 C++ 对象。
- QObject 父子关系：父对象销毁时会自动销毁子对象。
- `QNetworkReply::finished`：网络请求是异步完成的，不能当作同步返回值使用。
- QML 属性绑定：表达式依赖的值变了，界面会自动刷新。
- QML delegate：`index`、`modelData` 来自视图/Repeater，不是普通局部变量。

## 项目专用词汇

注释中统一使用下面说法：

| 术语 | 说明 |
|------|------|
| 服务容器 | `ApplicationContext`，负责创建并持有所有 C++ 服务 |
| API 客户端 | `BilibiliApiClient`，只封装 B站接口和请求参数 |
| 业务服务 | `AuthService`、`FavoriteService`、`PlaylistService` 等可被 QML 调用的服务 |
| 媒体解析 | 把收藏夹条目转换成真实可播放 URL |
| 播放控制 | 播放、暂停、进度、音量、状态通知 |
| 持久化 | 把 Cookie、播放列表、配置写到磁盘，下次启动恢复 |

## 不要做的事

- 不要给每个变量都写注释。
- 不要把代码改成“注释驱动”的超长段落。
- 不要在注释里夸大能力，比如把第三方公开算法写成原创。
- 不要把临时调试结论写成确定事实。
- 不要为了写注释改变函数行为。

## 验收标准

完成注释后，新人应该能按 `docs/reading-guide.md` 的顺序读代码，并说清楚：

- 程序从 `main.cpp` 到 QML 页面加载的流程。
- QML 如何通过 `applicationContext` 调用 C++。
- Cookie 登录和扫码登录如何汇合到 `checkLogin()`。
- 收藏夹数据如何从 B站 API 到 QML 页面。
- 播放地址如何解析，音频如何交给 `QMediaPlayer`。
- 播放列表如何自动切歌和持久化。
